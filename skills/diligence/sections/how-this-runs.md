## How this runs

One path, and it is the skill's own portable method made the only method.
Everything in the workflow below happens by reading and writing documents in
this session: no program runs, nothing is dispatched anywhere, and nothing is
fetched. Do not replace the workflow with an informal read of the whole room
because the machinery is not here; the method is what carries across.

Work sequentially. One document, one pair, one unit against one lens, one
check at a time, each against the same contract and the same result shape.
Never take more than 12 issues into a single pass, and fewer for long,
image-heavy or fact-dense units.

Work a tranche at a time. The lawyer chooses how many documents a session
takes; no ceiling is inferred here because none is published. Each tranche's
rows are appended to the master register, which the lawyer keeps and attaches
at the start of the next session. When the register is not attached, say so
before anything else, name the file that was expected, and say which tranches
are on the record and which are not; then continue on the reduced scope you can
actually see. State the tranche boundary on every delivery, not only the last.

The register carries the state the run depends on, and its counts are
arithmetic the lawyer can open and check. What it never becomes is a warrant
that the room was covered.
