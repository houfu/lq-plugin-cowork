## Read the applicable contracts

- Before inventory, read
  [execution-modes.md](references/shared/execution-modes.md), which is how this
  review runs and what it does not promise, and
  [schemas.md](references/shared/schemas.md), which defines the master register
  and every artifact.
- Before clustering messages, raising a privilege candidate, taking the setup
  confirmation, recording the lawyer's rulings or reconciling, read
  [comms-schemas.md](references/comms-schemas.md). The four privilege signals
  and the four rules that make the hold as strong as it can be made are there.
- Before compiling the review questions, read
  [framework-schema.md](references/shared/framework-schema.md). For a served
  request set, build the census first and keep every served element.
- Before each pass, read its contract: reading one document
  ([metadata-reader-prompt.md](references/shared/metadata-reader-prompt.md)),
  reviewing one unit against one lens
  ([finding-worker-prompt.md](references/shared/finding-worker-prompt.md)), or
  checking one finding
  ([finding-checker-prompt.md](references/shared/finding-checker-prompt.md)).
- Before producing any page for the lawyer, read
  [review-ui.md](references/shared/review-ui.md).

If the lawyer has attached an `lqplaybook.md`, or placed one in the session's
Input folder, read only its confirmed `[docreview]` entries. Do not read any
profile file, and never write to the playbook. A preference that emerges during
the run is offered as one exact `[docreview]` line the lawyer can add to their
own file; it shapes future work only once they have added it.
