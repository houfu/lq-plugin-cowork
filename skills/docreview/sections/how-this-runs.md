## How this runs, and what it does not promise

One path, and it is the skill's own portable method made the only method.
Everything below happens by reading and writing documents in this session: no
program runs, nothing is dispatched anywhere, and nothing is fetched. Preserve
every privilege hold and every point at which the lawyer decides. Say which
checks the original performed automatically and this run performs by reading —
in the first reply, and again on the delivery.

Work sequentially: one document, one unit against one lens, one check at a
time, each against the same contract and the same result shape. Never take more
than 12 requests into a single pass, and fewer for long, image-heavy or
fact-dense units.

Work a tranche at a time. The lawyer chooses how many documents a session
takes; no ceiling is inferred here because none is published. Each tranche's
rows are appended to the master register, and the lawyer attaches it at the
start of the next session. State the tranche boundary on every delivery.

Taking the production in: an attached file must be under 200 MB, and an
encrypted file cannot be read at all, even where the lawyer has access. Say
both in the first reply, attempt every file, list what did not open and park
it. A sensitivity label is not the same thing as encryption — attempt a
labelled file and report what actually happened, rather than parking it on an
assumption.

Work in the session's Output folder. Nothing there can be deleted, so name the
files that remain rather than describing anything as cleared away. Nothing is
transmitted anywhere; there is no channel by which it could be.

[references/shared/execution-modes.md](references/shared/execution-modes.md)
sets all of this out, including the calibration that must pass before scaling
and the account of what changed from the original.
