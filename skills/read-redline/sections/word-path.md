## The Word path (tracked changes)

Word records every change as a tag carrying an author and a date, so nothing is inferred from colour and there is no colour calibration. What there is instead is a question to answer before anything else: can you see those tags in this file at all?

1. **Report before extracting, and prove to yourself that you can see the marks.** Read the file and report the changes by kind and by author, the moved passages and the formatting-only count, and ask the lawyer to confirm the authors are who they expect.

   **You may not say "no tracked changes found" on a bare reading.** Before a nil return you must quote one inserted string and one deleted string from somewhere in the file, with the author of each. If you can do that and the rest of the document genuinely carries nothing else, say: the file has tracked changes and they are only these. If you cannot — if nothing in the file reads as an insertion or a deletion — then you do not know which of two things is true, and you must say which one you are reporting:

   - *The file is clean.* The changes were accepted before it was saved, or it is a first draft. There is nothing to review and nothing to compare it against.
   - *You could not tell.* You could not establish whether this file carries tracked changes. Say so in those words and ask the lawyer to open it in Word, turn on **All Markup** in the Review tab, and tell you what they see.

   A nil return that does not name which of the two it is reads to a lawyer as "there were no changes", which is the worst thing this skill can get wrong. Never let one stand alone.

2. **Extract the changed pairs.** Same shape as the PDF path, with the paragraph in place of page geometry: each pair carries its revisions (kind, author, date, text) and the document's existing comments, anchored to their paragraphs. Moved passages are moves, not changes. A formatting-only change is not a change. Save as `extract.json` in the Output folder, and write the step-1 report — counts, authors and the lawyer's confirmation — into `redline-calibration.md` beside it: on this path that report is the calibration the deliverable carries.

3. **Read everything, including the comments.** There are no pages to look at here. Read every changed pair and every existing comment; a counterparty's own comment often says why a change was made and belongs in the row's comment.

4. **Rate, group, present** exactly as steps 6, 7, 8 and 9 above. The marked-passage page and the Word issues list both already show old text beside new, so nothing is lost by the absence of colour. Where the author matters ("the other side's counsel deleted", "our associate inserted"), say so in the comment, since you read it.

5. **A marked-up Word copy, on request only.** The lawyer's Word file is their working document and you never write to it. If they ask for the review inside a document, produce a **new** Word document through the Word skill: the affected clauses with the proposed reading, one comment per row reading `[Tier] Provision — comment` (prefixed with the direction when the row carries one: `[favours-them · Tier] Provision — comment`). Ask for real tracked changes attributed to a review author, then tell the lawyer which of the two you got: marks Word shows in its review pane, or the same content as old text beside new. They see it the moment they open the file, so say it first.
