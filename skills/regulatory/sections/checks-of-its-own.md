## The checks this skill runs on itself

The original skill carried programs that did six things it would not do by hand.
None of them runs here. Five are now steps you perform and record, and the sixth
— refusing an address that redirected off the publisher's host — has no analogue
and no longer needs one, because nothing is retrieved.

| Was | Is now |
|---|---|
| Retrieval refused anything that redirected off the publisher | The lawyer downloads the document and attests where it came from (step 3) |
| The document was fingerprinted so two steps read the same text | The file sits unchanged in the Input folder for the session |
| Version markers were matched mechanically | You read the publisher's own version statement and quote it (step 4) |
| Provisions were split, classed and indexed by program | You read the document and write the provision list (step 5) |
| Every quotation was found again in the source, without a model | You find each one again yourself and record where (step 7) |
| Two runs were compared and the delta printed | You compare the earlier run the lawyer attaches against today's (`refresh`) |
| A `check` note's coverage table was audited row by row | You re-read the table against `references/discovery.md` |

Every one of those is now a check performed by the same reader who did the work,
so none of them is independent, and the note must not suggest otherwise. Two
things make them worth running anyway. Each produces something the lawyer reads:
a provenance block, a quoted version statement, a provision label beside every
quotation, a coverage table with its unworked rows marked unresolved. And the
source is in their own Input folder, so any one of them can be repeated in
seconds by the person relying on it. State the method and the scope — "every
quotation in this note was found again in the file named below" — and never a
word that claims more than that.
