### 5. Extract the provisions

Read the supplied document through and write out, in the Output folder, one list
of its provisions: for each, the label the publisher gives it, the heading, the
text, and whether it is a recital, a preamble, an operative provision, an annex
or a schedule. Index every term the instrument defines. Everything downstream
cites these labels, so settle the numbering convention before you start and say
which one you settled on.

Both halves of that matter. Nothing classed a recital may be quoted as imposing a
duty, and any ordinary word the instrument defines is not being used in its
ordinary sense.

Three things stop the run rather than being worked around:

- **Two provisions under the same label.** Usually the publisher's page
  furniture — a contents list, a breadcrumb or a page title repeating a heading
  the body also carries. It is the one break with no downstream signal, because a
  note quoting either one cites a real section, just not the one the words came
  from. Ask for the section or chapter page itself rather than an index or a
  search view. It is a finding about the document, not something to edit away.
- **A document you cannot read.** A scanned or image-only publisher PDF is a
  stop, not a slow start. Say that the text could not be read, ask whether the
  publisher offers an HTML or text-layer version of the same document, and do
  not describe pages you have not read.
- **A convention the text does not use.** Forcing one produces a run whose every
  quote is cited to a single undivided block. A single-section source is normal,
  not a failure: most code sections are published on their own page.

Four things are out of bounds, and testing found all four: rewriting the
publisher's headings so they fit a pattern; asking for a larger document to raise
the heading count; writing the provision list from memory rather than from the
document; and working from text pasted into the conversation rather than from the
file in the Input folder. Each puts you between the publisher and the quotation,
which is the one thing this skill exists to prevent.

**A chaptered act is not the code it amends.** A session law — a California
`SEC. 2.`, an Illinois Public Act — has *act* sections, each containing the code
section it enacts. The act's own numbering is what the run cites. Two
consequences worth stating in the note: a code-section citation must name the act
section carrying it, and a bill that carries several alternative versions of one
code section (California's `SEC. 2.` through `SEC. 2.3.`) has them all listed
side by side. Which one took effect is a question for the act's own
operative-condition sections, read in step 4 — never a choice made while reading.

Where a publisher file had to be converted to text before it could be read, say
so in the verification record: which file, what produced the text, and on what
date. A derived text that does not say it is derived is quoted as though it were
the publisher's own.
