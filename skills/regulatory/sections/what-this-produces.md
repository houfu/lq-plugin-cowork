## What this produces

Two labelled levels: **Your answer** (normally 150–250 words, essential citations,
assumptions and qualifications) then **Supporting analysis**. The initial chat
must state the substance of the answer, even when a fuller file is delivered.
Keep version qualifications brief unless they change or prevent the answer. The
provenance block, the version findings and the reading notes belong in a separate
verification record, not in the answer.

The source is the publisher's own document, downloaded by the lawyer and placed
in the session's Input folder. Everything this skill writes — the note, the
provision list and the verification record — goes to the Output folder, one set
per instrument, each filename carrying the instrument and the date of the run.
Write them even for an on-screen answer: a later refresh can only compare against
what the lawyer still has. Name the files when you deliver. Nothing written here
can be deleted afterwards, so write what the work needs and no more, and never
describe anything as cleaned up, removed or not retained. Where the lawyer wants
one instrument's material kept together, offer to create a dated folder for it
and move the files there after they are written.

`references/run-format.md` gives the shape of the note, the rules for quoting and
what a saved set holds. Read it before writing a note.
