## Modes

Run single-agent and sequential. Read first the documents that state the
position under test, post the map, keep reading the rest while the lawyer
considers it, then attack, adjudicate, deliver and check. Step 0's explainer
and the Transmission 1 checkpoint (Step 7) always apply: in an interactive run
the lawyer confirms the map before adjudication starts.

Target: the map in the lawyer's hands as soon as the documents that state the
position have been read — never held back for the rest of the bundle, which is
read while the lawyer considers the map. Findings begin once the lawyer has
confirmed and the full read is done. In an interactive run, deliver lead
findings as they are adjudicated rather than holding everything to the end.

A large bundle — roughly thirty documents or a hundred thousand words and up —
takes a longer, staged read: work document by document, keep short plain notes
on each, and reconcile them centrally before adjudicating. That changes
thoroughness only, never the method contract, the checkpoint or the output
format. A document that cannot be read whole in the context available is
`parked`, which yields an `incomplete` verdict naming it — never summarised and
then tested from the summary.

A caller on a non-interactive or scheduled surface should say so in the
instruction ("this is a non-interactive run — proceed without waiting"); the
checkpoint then yields to the batch branch and the whole review delivers in one
turn.
