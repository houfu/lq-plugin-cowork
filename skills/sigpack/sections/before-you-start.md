## Before you start
- Read `references/signature_page_rules.md` in full: what a signature page is, why party, signatory and capacity are three different things, and how the pages are grouped.
- Read `references/ledger_schema.md`: the ledger is one file per closing that the lawyer keeps. They attach it at the start of a session and get it back updated in the Output folder at the end. It is the only memory this skill has between sessions.
- **Say what you were given, first.** Name the ledger you were expecting. If no ledger was attached, say so in the first reply, before anything else: state that you are working from what is in front of you in this session, that nothing carries over from an earlier one, and carry on. The ledger holds continuity, not a legal hold, so its absence narrows the work rather than stopping it. If one was attached, say how many rows you read out of it before you write anything back.
- If the lawyer has attached an `lqplaybook.md`, or placed one in the session's Input folder, read only its confirmed `[sigpack]` entries: default grouping, copies, the duplicate rule, the filename pattern, cover-note wording, separator and file naming. Read no other preference or profile file, and never write to the playbook. Where this run settles a preference, offer it as one exact `[sigpack]` line the lawyer can paste into their own file.
- Client-identifying facts belong in the pages, the instruction table and the matter ledger only. Never in a preference file.
