# Deciding how a concept maps

A checklist for step 4. Take the queue one item at a time. Each item is a concept the source clause invokes; the question is what, if anything, in the core document carries the same conceptual scope.

Same names do not prove the same meaning. Different names can be the same concept. Decide from the definition text and the usage context in both documents, never from label similarity alone.

## The decisions

- **Equivalent** — a core-document expression covers the same conceptual scope as the source concept, with no limb, qualification or exclusion added or lost.
- **Narrower scope** — the best core-document candidate covers less than the source concept did. A literal substitution would silently drop scope the source clause carried.
- **Broader scope** — the best candidate covers more. A literal substitution would silently sweep in scope the source clause never had.
- **False friend** — a core-document term with a similar or identical label denotes a materially different concept. Naming this is exactly the failure this review exists to catch; never resolve a false friend as equivalent because the label looks right.
- **One to many** — the source concept is preserved only by two or more core-document terms used together. Cite every destination term; a one-to-many decision citing a single destination is not one.
- **Many to one** — this source concept and at least one other concept in the queue both belong under the same single core-document term. Say which other items share the destination.
- **No mapping** — the core document has no expression at all, defined or undefined, that covers this concept. Say what you looked at before concluding it.
- **Leakage flag** — leakage mode only; see the leakage-scan checklist.
- **Needs review** — more of the documents might resolve this, and it is worth going back for.
- **Not enough evidence** — what the two documents say cannot support a reliable decision at all.

## What a decision must carry

Every decision cites wording from both documents, quoted exactly, with the clause each quotation comes from. Equivalent, narrower, broader and false friend each need at least one supporting quotation from the source document and one from the core document. A no-mapping decision says where in the core document you looked.

Give a short, concrete note. Name the specific limb of the source definition that a narrower candidate drops. Say why a false friend's label is misleading. "Different scope" is not a note.

## Rules

A concept the source clause invokes through another defined term is itself an item in the queue. Follow the dependencies out rather than treating a definition as a single opaque unit.

Where the source document uses a term it does not define, that is not a mapping failure in the core document — say it plainly: the precedent relies on a term its own text never defines.

Nothing here is applied. Every decision, equivalent ones included, is a proposal in the mapping record for the lawyer to accept, edit or reject.
