How this differs from the original

The upstream skills were written for a coding agent on a lawyer's own machine: a shell, a Python interpreter, a working directory, bundled programs. Copilot Cowork is none of those things. This page is what that costs, in one screen, before you go looking at any one skill.

The capability picture

Every card in this repository is written against these facts, read off Microsoft's own documentation. They are the reason the adaptations look the way they do.

No local disk, and no working directory that outlives the task

Cowork cannot reach files on your device. It works with OneDrive and SharePoint: a session has an Input folder and an Output folder, and what it writes stays in your Cowork folder afterwards. While a task runs, files are processed in a temporary isolated environment that is removed when the task finishes and that you cannot look inside. So nothing here keeps a scratch path, a run directory or a ledger that survives the task — where the original kept state on disk, the adaptation either keeps it in the Output folder under a name you are told, or asks you to attach it.

Cowork also cannot delete anything in OneDrive or SharePoint. No skill here promises to clean up after itself; an intermediate file is named and left where you can see it.

Scripts: documented, but never specified

Microsoft's pages disagree with each other about whether a skill's bundled code runs at all — one page calls scripts/ "executable utilities", another says a skill runs as instructions to the AI — and no page anywhere names an interpreter, a language version, an installed library or a way to install one. A script whose runtime nobody documents cannot be relied on, so these packages ship no scripts. Every step that upstream handed to a program is written out as something the model does and you can check. Whether a script runs, and in what, is the first capability probe.

Web reach exists, is the tenant's to switch off, and nothing depends on it

Web search applies to Cowork but has no user-facing toggle and can be disabled by admin policy, so it may simply be off where you work. Browser use is off until an administrator turns it on. A skills-only package has no network channel of its own: the only declared one is a connector you would have to run yourself. So no card fetches anything, and no card promises a source came from the publisher's own bytes — where the original fetched, the adaptation asks you for the document, or cites by title and date without a link.

Sessions, and what "transcript" is allowed to mean

A skill works inside the conversation it is in: it can read what you attached and refer to earlier messages. Past sessions can be reopened, but what that restores to the model — as opposed to the screen — is undocumented, and nothing documents a way for a skill to read another session's log. Where a card here says "transcript" it means a document you supply, a deposition or a meeting record; never a log of a conversation.

The capability probes are the questions this picture leaves open, each one written so a tester can settle it.

What the build does to every skill

Before any hand-written adaptation, the same mechanical rewrites run over every skill. They are rule-based and pattern-anchored, so a change upstream either still matches or fails loudly rather than quietly doing nothing.

  • Files that do not belong in a package are dropped — upstream's per-skill licence copy, its agent definitions, and anything hidden. Each card drops more: the scripts/ folders, and the schemas that went with them.
  • Host-only frontmatter is removed {%- if transforms.drop_frontmatter %} ({{ transforms.drop_frontmatter | join(", ") }}){% endif %} — keys that mean something to a coding agent and nothing to Cowork.
  • The invocation grammar goes. Upstream text says $name and /name to call a sibling skill. Cowork has no such grammar: it routes on the description. Every one of those tokens is rewritten to the plain skill name, and any that survive are reported.
  • Vendor names are stripped and then checked for {%- if transforms.vendor_words %} ({{ transforms.vendor_words | join(", ") }}){% endif %}. Nothing shipped may name the agent it was written for.
  • Machinery that does not exist here is flagged — a scribe, a profile file, a run directory, an exit code, a named Python library. A skill that still mentions one is a warning somebody has to answer.
  • The description is replaced wholesale from the card, written for the way a lawyer asks rather than the way a developer reads, with an explicit hand-off to whichever neighbouring skill competes for the same request.
  • Every adapted file is stamped with an Apache-2.0 modification notice naming the upstream commit it came from, and each package carries upstream's licence and a notice at its root.

The claim-words rule

A skill may not word a promise it cannot back with something you can inspect. Upstream's wording leans on machinery that is gone: a script that counted what it covered could call the count a receipt, and the adaptation cannot. So the build refuses these words in any shipped file unless a card states a reason for keeping one:
